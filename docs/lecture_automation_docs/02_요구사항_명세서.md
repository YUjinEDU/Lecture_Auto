# 02. 요구사항 명세서

## 1. 기능 요구사항
### FR-01 입력 관리
- 사용자는 PPTX 파일 1개를 입력할 수 있어야 한다.
- 사용자는 강의명, 과목명, 수강 대상, 목표 강의 시간, 설명 스타일을 지정할 수 있어야 한다.

### FR-02 PPT 파싱
- 시스템은 슬라이드별 제목, 본문, bullet level, 표/차트/이미지 존재 여부를 추출해야 한다.
- 시스템은 speaker notes가 있으면 함께 추출해야 한다.

### FR-03 렌더링
- 시스템은 각 슬라이드를 PNG 이미지로 렌더링해야 한다.
- 시스템은 슬라이드 번호와 매칭되는 렌더링 파일명을 보장해야 한다.

### FR-04 시각 해설 노트 생성
- 시스템은 모든 슬라이드 이미지를 VLM에 입력해 visual summary, key elements, layout relations, teaching points, possible confusions를 생성해야 한다.
- 출력은 JSON 스키마를 준수해야 한다.

### FR-05 최종 스크립트 생성
- 시스템은 슬라이드별 구조 정보와 VLM 노트를 결합해 설명 스크립트를 생성해야 한다.
- 출력에는 `slide_id`, `target_seconds`, `script`, `keywords`, `transition_to_next`가 포함되어야 한다.

### FR-06 검증 및 재실행
- 시스템은 각 단계 산출물을 저장하고 검증해야 한다.
- 특정 슬라이드만 선택하여 재생성할 수 있어야 한다.

## 2. 비기능 요구사항
- 재현성: 같은 입력과 같은 설정이면 동일 파이프라인을 재실행할 수 있어야 한다.
- 추적성: 모든 단계는 로그와 설정 파일을 남겨야 한다.
- 확장성: 이후 TTS, alignment, Remotion 렌더링 모듈을 쉽게 붙일 수 있어야 한다.
- 유지보수성: 모듈 경계와 JSON 계약이 명확해야 한다.
- 검수성: 교수님이 텍스트만 보고 수정 가능해야 한다.

## 3. 입출력 계약
### 입력
- `.pptx`
- 강의 메타데이터 YAML 또는 CLI 인자

### 중간 산출물
- `slide_manifest.json`
- `rendered/slide_XXX.png`
- `visual_notes.json`
- `slide_scripts.json`

### 최종 산출물
- 검수용 Markdown
- 단계별 JSON
- 후속 TTS 입력용 스크립트 파일
