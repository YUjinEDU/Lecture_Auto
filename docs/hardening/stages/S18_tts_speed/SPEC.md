# S18 SPEC — TTS 단계 최적화(측정 기반)

기준: master HEAD. TTS+받아쓰기 판정이 웰클락의 ~95%.

## 감독 실측 (2026-10-05, 기존 트레이스 3,870 시도, GPU 미사용)
- 시도 시간 ≈ **1.93 × 출력 음성 초 + 4.1s** (상관 0.67) → 생성 RTF ≈ 2(실시간의 절반 속도). 고정 오버헤드 ~4s(받아쓰기 ~3.3s 포함).
- 발음 사전 이후 런(e/f/g, 6개): 실패 시도 시간 비중 13~28%, 첫 시드 합격 85~94%.
  실패 시간 내역: long 5~12%, voiced 3~10%, silence 2~6%, cer 0~5%.
- **long 실패의 출력/예상 길이 비율: 중앙 1.47, 95% 1.55** — 거의 다 생성 상한(`max_new_tokens` = 예상×1.5)까지 달린다.
  합격 시도는 95% 1.13, 판정 상한 1.35. 즉 예상×1.35를 넘는 생성분은 **반드시 불합격**인데 1.5까지 계속 생성 중.
- GPU 2장 모두 현재 다른 학습 작업이 사용 중(2026-10-05) → 처리량 실험은 지금 못 함.

## 작업 항목
### S18-a 생성 상한을 판정 상한에 맞춤 (`raon_tts.py`)
- `max_new_tokens`의 배수 1.5 → `_MAX_DURATION_RATIO + 0.05`(=1.40)로, 상수화(`_TOKEN_CAP_RATIO`). 근거 주석에 위 실측.
  주의: 판정은 앞뒤 무음 제거 후 길이로 하므로, 제거 전 생성 길이 상한이 판정 상한보다 약간 커야 함 → 0.05 여유. `_MIN_MAX_NEW_TOKENS`/`_MAX_MAX_NEW_TOKENS`는 유지.
- 같은 시드에서 상한 아래로 끝나는 생성은 바이트 동일(상한은 잘라낼 뿐) → **캐시 키·`TTS_SYNTH_VERSION` 변경하지 않음**. 이 판단을 보고서에 근거와 함께 명시.
- 트레이스 `_trace` attempt 레코드에 `expected_seconds` 필드 추가(진단용).

### S18-b 처리량 벤치마크 스크립트 `scripts/bench_tts_throughput.py` (신규, GPU가 빌 때 실행)
- 고정 텍스트 묶음(저장소 안 테스트 문장 12개, 50~110자, 한국어) × 고정 시드로 `pipe.tts`만 호출(받아쓰기 없음).
- 모드: `--procs-per-gpu 1|2` (`multiprocessing`으로 같은 GPU에 프로세스 N개, 각자 모델 로드), `--gpu 0`.
- 출력 JSON(`--out`): 프로세스별 총 생성 초, 출력 음성 초, RTF, 피크 VRAM(`torch.cuda.max_memory_allocated`), 전체 처리량(음성초/벽시계초).
- 시작 전 `nvidia-smi`로 대상 GPU에 다른 프로세스가 있으면 **중단**(`--force`로만 무시) — 다른 사람 작업 방해 금지.
- 테스트: 모델/torch mock으로 집계 로직·GPU 사용 중 중단 로직만.

### S18-c 테스트
1. max_new_tokens 계산: 예상 10s → 상한 = ceil(10×12.5×1.40)+8 범위(실제 `_CODEC_FRAME_RATE` 상수 사용), 최소/최대 클램프 유지
2. 기존 게이트/재시도 테스트 전부 통과(동작 변화 없음)
3. bench 스크립트 집계·중단 로직
4. 전체 pytest 통과

## 금지
게이트 임계값(`_MAX_DURATION_RATIO` 등)·시드·캐시 키·합성 버전 변경, 실제 GPU 실행, `data/`·`output/` 쓰기, 새 의존성.
