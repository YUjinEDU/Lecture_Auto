### 2.2 Raon 구현에서 이미 있는 것

근거: [`raon_tts.py`](../lecture_auto/pipeline/raon_tts.py).

- 길이와 문장 경계를 고려한 분할, seed를 바꾸는 재시도, 제한된 추가 분할.
- `speaker_audio`와 continuation용 참조를 구분.
- 길이·에너지·침묵 기반 품질 검사와 일부 불량 구간 재생성.
- 음량 정규화, 구간 연결 처리.

따라서 "TTS 품질 관리가 전혀 없다"는 평가는 틀리다. 현재 검사가 실제 불량을 얼마나 잡는지, 실패/재생성 결과가 안전하게 관리되는지가 문제다.

확인 당시 `TTS_SYNTH_VERSION = "v11-sweetspot-80-100"`. 이름이나 코드 주석의 sweet spot은 실험적 최적성의 증거가 아니다. 당시 기본 분할 목표는 75~105자 범위였지만 이를 영구적인 계약으로 고정할 근거는 부족하다.

### F1. STT 검증이 실제 대본 일치 검증을 충분히 하지 못함

- 근거: `lecture_auto/pipeline/raon_tts.py:101`, `check_transcription_fidelity`.

- STT 예외, 빈 전사문, 빈 기대 텍스트가 실패 사유 없는 리스트로 반환될 수 있다.
- 앞선 간이 확인에서 비슷한 길이의 무관한 전사문과 빈 전사문이 통과했다. 이는 ASR 모델 정확도 실험이 아니라 **검사 로직의 한계 확인**이다.
- `synthesize_raon_slide(..., verify_stt=False)`가 기본이며 환경변수 `RAON_VERIFY_STT`도 관련된다.
- 권고: 내용 비교를 추가하고 `pass / fail / unavailable`을 구분한다. ASR 실패를 음성 합격으로 표시하지 않는다. CER 하나만으로 자동 폐기하지 않고 사람이 확인할 정보를 남긴다.

### F2. 실패한 재생성과 이전 성공 캐시가 혼재할 가능성

- 근거: `scripts/batch_generate_lectures.py:398` 이후 캐시/합성 처리.
- 성공할 때만 `.hash`를 쓰지만, 기존 hash가 존재하는 상황의 실패 재생성에서 그것을 제거하지 않는다.
- 앞선 임시 디렉터리 재현에서 같은 키의 기존 성공 파일을 실패 바이트로 덮어쓴 뒤 기존 hash가 유효하게 남았다.
- 권고: 성공본을 덮어쓰기 전에 새 후보를 검증하고 성공 시 선택 상태를 원자적으로 변경한다. hash 삭제만으로 기존 좋은 오디오를 잃는 문제까지 해결되지는 않는다.
- 캐시에는 대본·참조 바이트·모델 ID·일부 생성 설정·합성 버전이 들어가지만, 모델 immutable revision 및 `max_seconds` 등 실제 결과에 영향을 주는 설정의 누락 여부를 점검해야 한다.

## 5. 논문 근거

### P1. Clark et al., SSW 2019 — 장문 평가 단위

[Evaluating Long-form Text-to-Speech: Comparing the Ratings of Sentences and Paragraphs](https://www.isca-archive.org/ssw_2019/clark19_ssw.html)

문장 단독, 문단 전체, 문맥 제시 후 음성 평가의 결과가 같지 않고 반드시 상관하지 않음을 보고한다. 우리에게 필요한 결론은 **짧은 문장 점수만으로 강의 청취 품질을 대표할 수 없다**는 것이다. 특정 길이로 분할해야 한다는 근거는 아니다.

### P2. Battenberg et al., NAACL 2025 — 길이 일반화 실패

[Robust and Unbounded Length Generalization in Autoregressive Transformer-Based Text-to-Speech](https://aclanthology.org/2025.naacl-long.591/)

연구 대상 AR Transformer TTS에서 긴 입력에 따른 반복·누락·불안정한 출력을 다루고 정렬 메커니즘 개선을 제안한다. 길이별 실패 평가가 필요하다는 근거다. 해당 모델 구조의 결과를 Raon의 현재 증상 원인이나 동일한 개선 효과로 전이해서는 안 된다.

### P3. Pan et al., ACL Findings 2026 — 장문 품질의 여러 축

[Comprehensive Benchmarking of Long-Form Speech Generation in Diverse Scenarios — PDF](https://aclanthology.org/2026.findings-acl.112.pdf)

PDF는 SwanBench-Speech라는 이름을 사용하며 1,101개 샘플, 17개 시나리오와 음향·내용·표현력의 평가를 제시한다. 웹 메타데이터의 abstract에는 LFSBench라는 명칭이 있어 **명칭 차이를 주의**한다. 인용은 제목과 PDF를 기준으로 한다.

우리에게는 음색/운율 일관성과 내용 정확성을 나눠 평가해야 한다는 참고가 된다. 자동 평가기의 한국어 교수 강의 유효성은 이번 조사에서 검증하지 않았다. 일곱 지표를 모두 구현할 필요는 없다.

### P4. Wang et al., 2026-09-15 프리프린트 — 최신 모델도 장문은 별도 문제

[Taming Long-form Text-to-Speech](https://arxiv.org/abs/2609.16989)

Qwen3-TTS와 VoxCPM2의 장문 입력 실패, 추론 중 오류 위치 복귀와 재생성(LACI), 구간별 화자 유사도(wSIM)를 다룬다. 짧은 입력의 평균 점수가 장문 안정성을 보장하지 않는다는 참고다. 최신 프리프린트이며 **Raon 적용/재현 결과가 아니다**. attention 수준 기법을 즉시 이식하는 작업은 권하지 않는다.

### P5. AutoLectures, 2025 — 슬라이드 영상 자동화의 유사 연구

[Generating Narrated Lecture Videos from Slides with Synchronized Highlights](https://arxiv.org/html/2505.02966)

슬라이드→대본→TTS→영상과 발화에 동기화된 시각적 강조를 구성한다. 주요 정량 결과는 1,000개 주석 샘플의 하이라이트 위치 정합이며, 보고된 F1>92%를 **TTS 자연스러움·한국어 발음·학습 효과 수치로 해석하지 않는다**. 비용 주장 역시 해당 설정의 보고값이지 우리 GPU 비용 예측이 아니다. 현재 음성 품질 개선보다 시각적 강조 기능을 먼저 개발할 근거는 부족하다.

### P6. 추가 참고 및 인용 주의

- [Factors Affecting the Evaluation of Synthetic Speech in Context, SSW 2021 PDF](https://www.isca-archive.org/ssw_2021/omahony21_ssw.pdf): 자연스러움/적절성 질문과 평가 맥락의 영향 참고. 앞선 조사에서 HTML abstract가 실제 PDF와 불일치했으므로 PDF를 확인할 것.

- [Raon 보고서](https://arxiv.org/html/2605.23912v1): 모델 저자 평가 참고. 앞선 조사에서 한국어 CER의 ASR과 UTMOSv2 사용을 확인. 다른 논문의 수치와 평가 조건이 달라 직접 순위화하지 않음.

## 7. 최신 TTS 모델 조사의 적용 범위

이 대화에서 Raon 외에 Qwen3-TTS, VoxCPM2, Fish 계열, CosyVoice, Chatterbox 등을 검토했다. **공통 한국어 데이터로 직접 비교한 순위표는 없다.** 출시 최신성, 샘플 품질, 논문 benchmark를 섞어 Raon보다 낫다고 결론 내리지 않았다.

채택할 설계 교훈은 다음으로 제한한다.

- 화자 정체성을 주는 참조 음성과 말의 연결을 주는 continuation 문맥은 구분한다.
- 한국어 지원 표시는 전문용어·수식·영문 혼합 강의의 품질 보장이 아니다.
- 긴 입력 하나로 생성하는 방식과 짧게 나누는 방식에는 일관성/오류 복구의 trade-off가 있다.
- 모델이 바뀌어도 대본·음성 후보·검수 결과·최종 선택 기록을 보존하는 구조는 유용하다.
- 새 모델 조사가 현재 Raon 튜닝과 결과 관리 보강을 계속 미루는 이유가 되면 안 된다.

## 8. 권고하는 최소 설계

```text
슬라이드 → 편집 가능한 대본 → 발음용 텍스트
                                  ↓
                           Raon 후보 생성
                                  ↓
                        자동 점검 + 필요 청취
                                  ↓
                          사용할 후보 선택
                                  ↓
                  명시적 선택 목록으로 영상 조립
```

### 8.1 지금 고정할 계약

- 교수님이 수정하는 슬라이드별 대본 형식을 유지한다.
- 편집 단위와 모델의 합성 단위를 분리한다. 문단/문장/길이 분할 정책은 바꿀 수 있어야 한다.
- 대본 원문과 발음용 텍스트를 함께 남긴다. 발음 치환이 의미를 바꾸지 않았는지 검토한다.
- 검수 중 후보는 기존 선택본과 별도 파일로 저장한다.
- 검사 불능을 합격과 구분한다. 자동 gate 통과와 사람의 승인도 구분한다.
- 최종 영상은 선택한 파일 목록만 사용한다. 누락·오래된 파일은 조용히 통과시키지 않는다.
- JSON 상태 변경에는 기존 atomic write 패턴을 재사용한다.
- 승인된 음성과 manifest를 보존해 다시 조립할 수 있게 한다.

### 8.2 아직 고정하지 않을 값

분할 글자 수, 참조 음성 길이/구간, seed/temperature, continuation 사용 조건, pause 길이, 허용 CER, 침묵 임계값, 최대 재시도 수는 실험 대상이다. 현재 값은 baseline으로 보존하되 "최적"이라고 명명하지 않는다.

### 8.3 저장할 최소 정보 — 개념 예시, 확정 schema 아님

기존 schema/path helper를 먼저 확인하고 필요한 필드만 추가한다. 아래를 그대로 새 framework로 구현하지 않는다.

```json
{
  "slide_id": "slide-012",
  "script_hash": "...",
  "spoken_text_hash": "...",
  "segment_id": "slide-012-part-02",
  "candidate_id": "take-003",
  "audio_path": "...",
  "audio_sha256": "...",
  "model_revision": "...",
  "synthesis_settings_hash": "...",
  "speaker_reference_hash": "...",
  "continuation_candidate_id": null,
  "verification_status": "unavailable",
  "human_review_status": "pending",
  "selected": false
}
```

生成の provenance에는 실제 유효 설정, 코드 버전, 정규화/분할 버전, seed, 검사기 버전도 추적할 수 있어야 한다. 캐시 키에는 **생성 결과에 영향을 주는 값**을 포함한다. 검사기만 바뀌었으면 기존 WAV를 재검사할 수 있어야 하며 무조건 재합성할 필요는 없다.

동일 seed로 새 생성 결과까지 항상 바이트가 같다고 약속하지 않는다. 입력·설정의 추적 가능성과 승인된 산출물의 재조립 가능성을 먼저 보장한다.

### 8.4 지금 추가하지 않을 것

범용 다중 TTS registry, 전체 timeline editor, RVC 후처리, 자동 LLM 대본 재작성, 자동 MOS 단일 합격선, 새 queue framework, 플레이어, attention-level 모델 수정은 우선순위에서 제외한다. 현재 필요가 실측된 경우에만 다시 검토한다.

## 9. 평가 계획

### 9.1 목표와 지표

**주요 제작 목표: 승인 가능한 강의 음성을 얻기 위해 사람이 수정해야 하는 양과 시간을 줄이는 것.**

| 차원 | 권장 측정 | 주의 |
|---|---|---|
| 내용 정확성 | 한국어 CER, 전문용어 오독, 누락/반복 | 공백·숫자·영문 정규화 규칙 고정. 원문과 정규화문 모두 보존 |
| 청감 | blind A/B 선호, 늘어짐/어눌함/부자연스러운 끊김 표시 | CER로 대체하지 않음. 동률 허용 |
| 장문 일관성 | 연속 구간의 말속도·음색·연결감 | 짧은 클립 점수와 별도로 평가 |
| 실사용 불량 | 고정 평가 구간의 수정 필요 비율, 강의당 심각한 오류 수 | 합성 청크 수를 분모로 쓰면 분할 변경으로 왜곡 가능 |
| 운영 비용 | 승인 음성 1분당 사람 작업 시간, 전체 생성 시간, 총 시도 수 | 버린 후보/검증/모델 로딩 비용 포함 여부 명시 |
| 검출기 | 불량 검출 recall, 정상 오탐률 | gate pass rate를 실제 품질로 해석 금지 |

CER = `(substitutions + deletions + insertions) / reference character count`. ASR 오류와 TTS 오류를 분리하기 위해 일부 표본은 사람이 직접 전사/청취한다. 모델 내장 STT만 쓸 경우 독립 평가가 아니라는 제한을 적는다.

실효 RTF는 총 처리 시간/최종 채택 음성 길이로 보고할 수 있다. 순수 추론 RTF와 혼동하지 않는다. 평균뿐 아니라 최악 구간, 실패 횟수도 함께 남긴다.

### 9.2 최소 비교 실험 절차

1. 현재 대본·설정·참조 음성·코드와 기존 선택 음성을 고정해 baseline으로 보존한다.
2. 실제 강의에서 일반 표본과 알려진 어려운 표본을 따로 구성한다. 숫자/수식, 영어 혼합, 긴 설명, 짧은 전환, 문장 경계를 포함한다.
3. 교수님이 지적한 구간은 타임스탬프와 증상을 먼저 기록한다. 아직 정확한 목록은 확보되지 않았다.
4. 한 번에 하나의 주요 요인을 비교한다: 참조 음성, 발음 표기, 분할, continuation, 생성 설정 등.
5. 같은 대본과 비교 가능한 seed/시도 예산을 쓴다. 처음 생성된 결과와 재시도 후 채택 결과를 각각 평가한다.
6. 후보 순서를 가리고 청취한다. 연결감 평가는 경계 전후를 포함한다.
7. 설정 선택에 쓰지 않은 강의로 재확인한다. 네 편을 전부 튜닝에 써 놓고 독립 검증이라고 하지 않는다.
8. 최종 MP4를 실제 재생해 슬라이드 순서·누락·음성 버전·볼륨·연결을 확인한다.

초기 표본 수나 합격 임계값은 이 문서에서 통계적으로 확정하지 않는다. 작은 pilot으로 결함 빈도와 평가 편차를 파악한 뒤 정한다. 여러 seed/평가자가 없는 작은 결과는 screening으로 보고한다.

### 9.3 원인 가설과 구분 방법

| 가설 | 구분 실험 | 지금 단정하면 안 되는 것 |
|---|---|---|
| 참조 음성에 느린 말투/잡음이 있음 | 동일 대본·설정에서 참조만 변경 | 깨끗한 참조면 모든 문제가 해결됨 |
| 발음용 텍스트가 부적절 | 의미 유지한 표기 A/B | 자동 재작성은 항상 품질을 높임 |
| 입력 길이/경계가 문제 | 동일 내용에 여러 분할 정책 비교 | 75~105자가 최적 |
| continuation이 불량을 전달 | 동일 화자 참조에서 continuation 조건 비교 | 항상 켜거나 끄는 것이 정답 |
| 후처리가 말의 리듬을 손상 | raw와 processed 오디오 비교 | 침묵은 전부 제거해야 함 |
| 모델 자체 한계 | 앞 요인을 통제해도 반복되는 결함 확인 | 현행 gate 실패를 곧 모델 한계로 간주 |

완료 조건: 임시 파일과 mock만 쓰는 회귀 확인에서 (a) 실패 재생성 후 기존 선택본 유지, (b) 대본 변경 시 오래된 음성 거부, (c) 디렉터리의 무관한 WAV 제외, (d) 필수 음성 누락 시 명시적 실패를 확인한다.

### B. 검증 의미 보강

대상: `check_transcription_fidelity`, 결과 기록, 이에 의존하는 호출자.

- STT 불능/빈 출력/내용 불일치/실제 반복을 구분한다.
- 자동 결과와 사람의 승인 상태를 분리한다.
- 어떤 기준으로 재시도/선택했는지 남긴다.

완료 조건: 비슷한 길이의 무관한 전사문이 정상 내용으로 취급되지 않으며, STT 실패는 검사 불능으로 남고, 정상 표본의 오탐을 사람이 확인할 수 있다.

### C. Raon 품질 pilot

- A/B 평가 표본과 기준선을 먼저 만든다.
- 문제가 되는 구간을 직접 청취하고 원인 가설을 분리한다.
- 개선 설정의 최초 생성 품질, 선택 후 품질, 작업 시간을 함께 보고한다.

완료 조건: 교수님의 실제 불만 항목에 대한 비교 청취 결과가 있고, 독립 강의에서도 개선이 유지되는지 확인한다. "gate=0"만으로 완료 처리하지 않는다.

### D. 네 편 제작 및 확장

- 실제 입력 네 편, 대본 검수 상태, 참조 음성 사용 권한, 납품 형식을 확인한다.
- 생성→검수→부분 수정→선택→최종 MP4 검수 과정을 기록한다.
- 다른 교수에게 제공할 시점에 API/CLI의 Raon 경로와 동일한 유효성 규칙을 정리한다.
- 공개 전 비밀정보, 교수 음성·강의자료 포함 여부, 라이선스, 설치 문서, 최소 예제를 점검한다. 외부 코드 재사용은 해당 라이선스를 별도 확인한다.

완료 조건: 네 편의 최종 MP4와 사용한 대본/선택 음성이 대응하고, 다른 작업자가 기록만 보고 부분 수정 및 재조립할 수 있다.


파일을 수정하기 전 해당 디렉터리 지침과 모든 호출자를 확인한다. 테스트는 heavy external을 mock해야 한다. 기존 테스트 일부가 Redis에 접근한 기록이 있으므로 GPU/네트워크 없이 실행된다는 문서만 믿지 말고 fixture를 확인한다.

기존 baseline 재확인 명령은 `.venv/bin/python -m pytest -q`. 전체 collection 실패를 숨기지 않는다. 필요한 경우 원인을 명시한 제한 실행을 병행하되 이를 전체 통과라고 표현하지 않는다. 문서만 추가하는 이번 작업에서는 pytest를 다시 돌릴 필요가 없었다.

다음 구현 보고에는 변경 파일, 해결한 F 번호, 회귀 확인 결과, 새 음성 생성 여부, 청취 검증 여부를 분리해 적는다. 실패한 실험과 버린 후보의 비용을 숨기지 않는다.

## 12. 미해결 사항 및 판단을 바꿀 조건

- 교수님이 지적한 정확한 타임스탬프/증상 목록은 아직 없음.
- 추가 네 편의 확정 입력과 검수 완료 대본 목록은 이 문서에서 확정하지 않음.
- 현재 GPU/모델 checkpoint revision/실행 환경의 실측 재검증은 하지 않음.
- 최신 모델 간 한국어 강의 비교 실험은 하지 않음.
- 현행 검사기의 실제 불량 recall/정상 오탐률은 미측정.
- 청크 길이, 참조 음성, continuation 중 무엇이 주원인인지 미확정.
- 비밀정보 파일의 제거와 키 폐기 완료 여부는 미확인.

결과 관리 보강 후에도 통제된 실험에서 Raon의 심각한 발음/반복 결함이 남고 수정 비용이 요구 수준을 넘을 때 모델 수준 변경을 재논의한다. 사용자가 결정한 Raon 방향을 근거 없이 먼저 뒤집지 않는다.
