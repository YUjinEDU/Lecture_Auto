# Prior Art 조사 (2026-10-05)

방법: Exa 도구가 "Connection closed"로 실패하여 WebSearch/WebFetch로 대체했다. arXiv abs 페이지와 GitHub README를 직접 열어 확인한 항목은 [확인], 검색 스니펫만 본 항목은 [미확인]으로 표시한다. WebFetch는 요약 모델을 거치므로 수치는 원문 재확인을 권장한다.

## 1. 요약

- 가장 가까운 선행연구는 Paper2Video(PaperTalker)와 AutoLectures(arXiv 2505.02966)다. 문장 단위 자막, 커서/하이라이트 동기화가 이미 존재하므로 "자막/하이라이트" 자체는 새로움이 아니다.
- Paper2Video와 PresentAgent는 모두 "논문/문서 -> 발표 영상" 문제를 다룬다. 우리는 "교수의 기존 PPT/PDF -> 40분 한국어 강의"이고, 교수 음성 클론 + 말투 + 사람 검수가 핵심이라 문제 설정이 다르다.
- 두 논문 모두 TTS 출력을 문장 단위로 ASR 검증해 재생성하는 단계가 없다. Paper2Video는 F5-TTS, PresentAgent는 MegaTTS3를 한 번 합성하고 끝낸다 [확인].
- TTS ASR 자가검증 자체는 선행이 있다. 2606.18323(best-of-N ASR 검증), 2609.16989(LACI)가 그 예다. "ASR 검증 루프" 단독은 새롭지 않고, "강의 파이프라인에서의 운영 규칙 + 발음사전 + 사람 승인(sha256 고정)"이라는 조합으로 주장해야 한다.
- 새로움 후보는 시스템 수준에서 다음과 같다: 한국어 + 교수 음성/말투 보존 + 검증된 오디오 승인 워크플로(재현성/감사 로그) + 강의 시리즈 연속성 + 교수 수정 반영 학습.
- 평가는 Paper2Video의 PresentQuiz / PresentArena를 한국어 강의용으로 재사용할 수 있다. 다만 IP Memory와 Meta Similarity는 맞지 않는다.
- 가장 현실적인 투고처는 KCC 등 국내 학회 또는 HCI Korea다. 국제 데모 트랙은 사용자 연구와 정량 평가가 있어야 가능하다.

## 2. 핵심 논문 2편 상세

### 2.1 Paper2Video: Automatic Video Generation from Scientific Papers [확인]
- 링크: https://arxiv.org/abs/2510.05096 / 코드: https://github.com/showlab/Paper2Video
- 저자: Zeyu Zhu, Kevin Qinghong Lin, Mike Zheng Shou (showlab, NUS).
- 입력: 논문 LaTeX 소스 + 발표자 이미지 + 음성 샘플.
- 파이프라인(PaperTalker):
  - LLM/VLM(GPT-4.1 또는 Gemini 2.5-Pro 권장)으로 슬라이드 생성, 레이아웃 정제, 트리 탐색 기반 visual choice.
  - VLM이 슬라이드에서 문장 단위 자막과 "visual-focus prompt"를 생성.
  - 커서 grounding: 공간은 UI-TARS, 시간은 WhisperX로 정렬하여 문장별 커서 위치(x,y)를 얻는다.
  - 음성: F5-TTS로 발표자 음성을 클론, 슬라이드별 오디오 생성.
  - 선택적으로 Hallo2 기반 talking head.
  - 슬라이드 단위 병렬 생성으로 약 6배 속도 향상.
- 벤치마크: 논문 101편과 저자 제작 발표 영상. 영상 평균 6분 15초, 4~28 슬라이드. 데이터셋은 HuggingFace에 공개.
- 지표 4종:
  - Meta Similarity: VLM이 슬라이드-자막 쌍을 채점, 음성은 임베딩 코사인 유사도.
  - PresentArena: VideoLLM 쌍대 비교(위치 편향 완화).
  - PresentQuiz: 영상 시청 후 논문 내용 객관식 정답률.
  - IP Memory: 저자-작업 연상 기억.
- 결과: PresentArena 승률 50%, PresentQuiz 세부 질문 84.2%. 사람 평가에서 사람 제작 다음으로 2위. 단일 슬라이드 영상이 아닌 6분급 영상.
- 라이선스: 코드 MIT. 환경은 Python 3.10, A6000 48GB 권장.

### 2.2 PresentAgent: Multimodal Agent for Presentation Video Generation [확인]
- 링크: https://arxiv.org/abs/2507.04036 / 코드: https://github.com/AIGeeksGroup/PresentAgent
- 저자: Jingwei Shi, Zeyu Zhang, Biao Wu 외 (AIGeeksGroup).
- 입력: 장문 문서(웹페이지 등).
- 파이프라인: 문서 분할 -> 슬라이드형 프레임 계획/렌더 -> LLM 내레이션 + TTS(MegaTTS3) -> 오디오-비주얼 정렬 영상 합성. 웹 UI와 Colab 데모 제공.
- 평가: 문서-발표 쌍 30개 [확인]. PresentEval은 VLM 프롬프트 기반으로 content fidelity, visual clarity, audience comprehension 3축을 평가한다. "인간 수준에 근접"이라고 주장.
- 라이선스: arXiv 표기 CC BY-NC-SA 4.0 (논문). GitHub README에는 라이선스 명시 없음. 코드 재사용 전 확인 필요.

## 5. 새로움 주장 가능 지점 (시스템/데모 논문 수준)

주장 가능(조합 단위):
1. 한국어 교수 음성 클론 장편 강의에서 문장 단위 STT 검증(CER<=0.25, 무음/길이)과 재시드 재생성, 발음사전, 사람 승인(해시 고정)을 하나의 재현 가능한 운영 파이프라인으로 묶은 점. 개별 요소는 선행이 있으므로 "통합과 운영 규칙, 실제 40분 강의 적용 경험"이 주장 대상이다.
2. 기존 PPT/PDF 슬라이드를 그대로 사용(슬라이드 생성 없음)하고 교수 말투를 보존하는 점. 선행은 슬라이드 생성이 중심이다.
3. 교수의 수동 스크립트 수정 반영 및 강의 시리즈 연속성(구현 후). PRELUDE 등 알고리즘은 선행이므로 "강의 시리즈에 적용한 사례와 효과 측정"으로 한정해야 한다.
4. 검수 가능성: 후보 보존, 타임라인 JSON, DRAFT 표시 등 감사 가능한 산출물.

중복/주장 약함:
- 문장 단위 자막, 슬라이드 위 하이라이트/커서 동기화: Paper2Video와 AutoLectures가 이미 수행. 우리는 PDF text-block bbox 기반이라는 구현 차이만 있다.
- ASR 검증 루프 단독, 보이스클론 강의 영상 자체, "LLM 스크립트 + TTS + ffmpeg" 파이프라인 자체.

주의: "최초"라는 표현은 쓰지 말 것. 검색은 제한적이었고 한국어 강의 도메인 문헌은 충분히 훑지 못했다.

## 6. 재사용할 평가 지표

- PresentQuiz(Paper2Video): 영상 내용에 대한 객관식 문제를 LLM이 생성하고 VideoLLM/사람이 풀어 정답률 측정. 한국어 강의로 이식 가능. 슬라이드 원문 기반 문제 + 시청 후 정답률로 정보 보존 평가.
- PresentArena: 두 영상(예: 검증 루프 on/off, 재스타일 on/off)을 VideoLLM이 쌍대 비교. 위치 편향 완화를 위해 순서 교환. 우리 절제(ablation) 실험에 적합.
- Meta Similarity 중 음성 유사도: 참조 음성 대비 화자 임베딩 코사인. 우리 음성 클론 품질 측정에 사용 가능. 슬라이드-자막 VLM 채점은 선택.
- PresentEval(PresentAgent): content fidelity / visual clarity / audience comprehension의 VLM 채점. 구현이 가벼움.
- AutoLectures: 하이라이트 정렬 F1(수동 주석 기반). 하이라이트 기능을 만들면 소규모 주석(예: 100~200건)으로 동일 방식 평가.
- TTS 쪽: ASR 검증 전/후 WER/CER, 실패율, 평균 재생성 횟수(2606.18323, LACI의 worst-of-N WER 형식 차용).
- IP Memory는 저자 인지 측정이라 부적합.
- 그 외 우리 고유 지표 제안: 사람 승인까지 소요 시간, 문장당 재생성 횟수, 교수 수정 편집 거리(PRELUDE의 edit distance 방식 차용).

## 7. 투고처 제안 (적합성에 대해 솔직하게)

마감/세부 일정은 확인하지 못했다(미확인). 반드시 공식 CFP를 확인할 것.

1. KCC(한국정보과학회 한국컴퓨터종합학술대회): 가장 현실적. 시스템 설명과 초기 평가 수준으로 충분. 한국어 강의 도메인에 적합.
2. HCI Korea: 교수 검수 워크플로와 사용자 경험(승인/수정 루프)을 사용자 연구와 함께 제시하면 적합. 사용자 연구가 없으면 약하다.
3. 국제 데모/교육 트랙(예: AIED, EMNLP/ACL 계열 System Demonstrations, Interspeech Show & Tell 등 중 하나): 적합도는 낮음~중간. Paper2Video 수준의 벤치마크/지표 비교와 영문 데모 영상이 있어야 경쟁력이 있다. 한국어 단일 도메인, 소수 강의로는 현재 근거가 부족하다. 구체 학회는 CFP를 보고 판단할 것.

현실적 권고: 먼저 국내 학회로 1회 발표하고, PresentQuiz/Arena + TTS 검증 전후 절제 실험 + 교수 사용자 평가를 쌓은 뒤 국제 데모 트랙을 노린다.
