# 제작 파이프라인 안정화 — 작업 관리

최종 목표: 웹 인터페이스로 강의 제작(검수·승인·부분 재생성·최종 영상). **이번 범위는 그 직전까지.**
전체 계획은 [PLAN.md](PLAN.md).

## 폴더 구조

```
hardening/
├── README.md              ← 지금 보는 파일: 상태판 + 규칙
├── PLAN.md                ← 단계 정의(S1–S5), 공통 규칙, 완료 조건
├── 00_context/            ← 입력 자료(수정 금지, 참고용)
│   ├── LECTURE_TTS_RESEARCH_HANDOFF.md   인수인계 문서 사본
│   ├── 260923_review.md                  외부 검토 문서
│   └── VERIFIED_FACTS.md                 감독이 코드·데이터로 직접 확인한 사실
├── decisions/             ← 확정된 결정(D-번호). 바꾸려면 새 결정 추가
└── stages/<단계>/
    ├── SPEC.md            ← 작업 지시서(감독 작성, 작업자에게 전달)
    ├── REPORT.md          ← 작업자 보고(변경 파일·테스트·남은 문제)
    └── REVIEW.md          ← 감독 검토(diff 확인, 테스트 재실행, 판정)
```

## 진행 규칙

1. 감독(Opus)이 `SPEC.md` 작성 → 작업자(Sonnet)가 별도 git worktree에서 구현·커밋.
2. 작업자 보고를 `REPORT.md`에 기록.
3. 감독이 `REVIEW.md` 작성: 새 테스트가 **기준 코드에선 실패, 변경 후 통과**하는지, 전체 pytest가 기준선 대비 악화 없는지.
4. 사용자 승인 후 병합. 상태판 갱신.
