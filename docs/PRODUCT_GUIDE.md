# Lecture Auto 제품 기능 안내 (2·4·5단계, 배포)

계정·API 키·음성 업로드·가입은 `docs/WEB_UI.md`, 단계 간 약속은 `docs/PRODUCT_CONTRACTS.md`.

## 1. 음성 엔진 (강의마다 선택)

| 엔진 | `project.json` | 어디서 도나 | 목소리 |
|---|---|---|---|
| `raon` (기본) | `"tts_engine": "raon"`, `ref_voice` | 이 서버의 GPU (Raon-Speech-9B) | 올린 음성을 복제 |
| `gemini` | `"tts_engine": "gemini"`, `tts_voice`, `tts_instructions` | BAZE 게이트웨이 `POST /audio/speech` (`gemini-3.8-flash-tts`) | 기본 음성 30종 중 선택 (복제 없음) |

- Gemini는 슬라이드 대본을 Raon과 같은 문장 구간(약 75~105자)으로 나눠 구간마다 요청하고(동시에 최대 4개), 구간 사이에
  0.2초 무음을 넣어 잇는다. 자막과 하이라이트가 이 무음으로 문장 시각을 찾기 때문에 엔진과 상관없이 그대로 동작한다.
- 말투는 `tts_instructions`(예: "대학 강의처럼 차분하고 또박또박하게")로 정한다. 비우면 기본 지시를 쓴다.
- 캐시: Gemini 음성은 "모델 + 음성 + 말투 + 대본"이 같으면 다시 만들지 않는다. 음성이나 말투를 바꾸면 그 강의 음성 전체가
  "확인 필요"가 되어 다시 만들어진다. Raon 쪽 캐시 키는 바뀌지 않았다(기존 음성 그대로 유효).
- 키: 작업 프로세스는 `BAZE_API_KEY`(사용자 키 또는 서버 `.env`)로 TTS를, `FACTCHAT_API_KEY`로 대본 생성을 부른다.
- 실측(2026-11-07, 11번 강의 사본 18장, 약 40분 분량): 18장 모두 품질 검사 통과, 18장 모두 무음으로 문장 경계 검출, 말 속도 6.3~7.2자/초(Raon 기준 7자/초와 같은 수준).

## 2. 학생 강의 페이지 (공유 링크)

- 강의 화면의 "학생 공유·복습 자료" 버튼(`static/manage.html?lecture=<id>`)에서 공유 링크를 만들고 회수한다. 영상이 조립된 뒤에만 만들 수 있다.
- 공유 링크를 만들면 `/w/<토큰>` 주소가 생긴다. 로그인 없이 그 강의 하나만 볼 수 있고, 링크를 회수하면 바로 막힌다.
- 화면: 영상, 지금 설명하는 슬라이드 부분 표시(노란 상자, 끌 수 있음), 자막, 재생 속도, 목차(슬라이드 제목, 누르면 이동),
  대본 전문(문장을 누르면 그 시점으로 이동, 재생 위치를 따라 강조), 용어·퀴즈(승인한 것만), "AI 합성 음성" 표시, 신고.
- 데이터: `output/<id>/<id>.viewer.json`(문장 시각·하이라이트 위치·제목). 영상을 다시 조립하면 다음 요청 때 자동으로 새로 만든다.
- 신고는 링크마다 1시간에 10건까지 받는다(관리자 신고 목록에 "학생 페이지 신고"로 쌓임). 관리자가 강의를 비활성화하면 링크도 바로 막힌다.
- API: `GET /api/public/<토큰>`, `GET /api/public/<토큰>/video`(구간 요청 지원 — 탐색 가능), `POST /api/public/<토큰>/report`.

## 3. 용어·퀴즈

- "용어·퀴즈 초안 만들기" 작업(`study`, CLI `batch_generate_lectures --only <id> --study`)이 확정된 대본으로 용어 12개·객관식 8문제 이내의 초안을 만든다.
  대본에 없는 내용은 만들지 않도록 지시하고, 보기 4개·정답 번호가 맞지 않는 문항은 버린다.
- 같은 관리 페이지에서 초안 만들기·수정·공개 체크·저장을 한다.
- 초안은 전부 "미승인"이다. 교수자가 고치고 승인한 항목만 학생 페이지에 나온다. 초안을 다시 만들어도 승인한 항목은 남는다.
- 저장: `data/work_batch/<id>/study.json`.
- 실측: 11번 강의 사본으로 BAZE 대본 모델에서 약 17초, 용어 12개·퀴즈 8문제.

## 4. 설치형 배포 (Docker, GPU 없이)

```bash
cp .env.example .env      # LECTURE_WEB_PASSWORD(첫 관리자), LECTURE_WEB_SIGNUP, BAZE_API_KEY, FACTCHAT_* 채우기
docker compose up -d --build
```

- 이미지(약 1.6GB)에는 웹, 대본 생성, Gemini TTS, LibreOffice·poppler·ffmpeg·한글 글꼴이 들어 있다. Raon 음성 복제(GPU)는 들어 있지 않다.
- 데이터는 `./docker-data`(컨테이너 `/data`)에 쌓인다. 처음 켤 때 설정 파일과 기본 참조 음성을 채워 넣는다.
- 포트는 `127.0.0.1:8800`에만 연다. 외부에는 HTTPS 리버스 프록시를 앞에 둔다.
- GPU 서버(지금 연구실 서버)는 기존처럼 `.venv` + `uv sync --all-extras`로 돌린다. `torch`는 Raon으로 합성할 때만 불러온다.

## 5. 운영 메모

- 서버 비밀키(`data/web/secret.key` 또는 `LECTURE_WEB_SECRET`)를 바꾸면 모든 로그인이 풀리고, 저장된 사용자 API 키도 풀 수 없게 된다.
  이때 키는 자동으로 지워지고 사용자는 설정에서 키를 다시 등록하면 된다(작업이 실패하지 않고 "키를 등록하세요" 안내가 나온다).
- 가입은 10분에 20건까지 받는다(공개 가입 때 계정 대량 생성 방지).
- 학생 페이지·관리 페이지의 JS/CSS는 `?v=` 버전 쿼리로 불러온다. 파일을 고치면 HTML의 버전 숫자도 올린다(브라우저 캐시).

## 6. 교수자 화면 편의기능 (2026-11-07)

- **내려받기** (강의 화면 위쪽 "영상 받기" 버튼 + "내려받기" 칸): 최종/검토용(DRAFT) 영상 MP4, 자막 SRT·VTT, 전체 대본 TXT,
  슬라이드별 음성 ZIP, 검수 보고서. 각 슬라이드의 현재·후보·이전 음성도 하나씩 받을 수 있다.
  API: `GET /api/lectures/<id>/export/{scripts.txt|subtitles.srt|subtitles.vtt|audio.zip}`, `.../slides/<n>/audio/<kind>?download=1`.
- **대본 편집**: 글자 수와 읽는 시간(초당 7자 기준, 계획보다 크게 길거나 짧으면 주황색) 실시간 표시, 고친 슬라이드 강조,
  "변경 모두 저장"(Ctrl+S/⌘+S, `PUT /api/lectures/<id>/scripts`로 한 번에 저장), 변경 버리기, 슬라이드별 수정 취소,
  찾아 바꾸기(모든 슬라이드), 대본 검색, 슬라이드로 바로 이동, "직접 수정함" 탭,
  "처음 생성된 대본으로"(첫 수정 전 대본을 `data/work_batch/<id>/scripts_original/`에 보관했다가 그대로 되돌림 — 되돌리면 다시 생성 대본으로 취급),
  "저장하고 음성 다시 만들기"(그 슬라이드만 새 음성 후보 생성).
- **진행 단계 표시**: 강의 카드에 미리보기·진행 막대, 강의 화면에 5단계 표시와 "다음 할 일" 안내.

## 7. 용량 한도 (관리자가 정함)

- 관리 화면 → **계정 직접 만들기**: 이메일·이름·비밀번호(자동 생성)·권한, "무제한" 체크(기본 켜짐). 가입 방식과 상관없이 만들 수 있다.
- **계정별 한도**: 무제한 체크, 또는 강의 수·음성 수·저장 공간(MB)을 각각 지정. 비워 두면 기본 한도를 쓴다. 0은 "더 만들 수 없음".
- **기본 한도**: 따로 정하지 않은 계정(공개 가입 등)에 적용. 처음 값은 환경변수(`LECTURE_WEB_MAX_LECTURES` 등)이고, 관리 화면에서 바꾸면 DB 값이 우선한다.
- 관리자는 항상 무제한. 사용자는 설정 화면에서 자기 사용량/한도를 본다.
- 파일 하나의 업로드 크기 한도(`LECTURE_WEB_MAX_UPLOAD_MB`, 음성 `LECTURE_WEB_MAX_VOICE_UPLOAD_MB`)는 서버 보호용이라 계정과 상관없이 같다.
- API: `POST /api/admin/users`, `PUT /api/admin/users/<id>/limits`, `GET|PUT /api/admin/limits`, `/api/me`의 `limits`·`usage`.

## 8. 속도 (2026-11-07 실측, GPU 서버 CPU 기준)

| 단계 | 전 | 후 | 바꾼 것 |
|---|---|---|---|
| 영상 조립 (39분 강의) | 10분 30초 | 35초 | 정지화면이라 30fps → 2fps + `-tune stillimage`, AAC 인코더를 fast 코더로(진짜 병목). `-shortest` 제거로 끝 0.2초 잘림도 해결 |
| Gemini 음성 (슬라이드 4장, 9.4분 분량) | 약 3분 40초 | 33.5초 | 슬라이드 3장 동시 + 슬라이드 안 문장 4개 동시, 전체 동시 요청은 8개로 제한(`BAZE_TTS_MAX_IN_FLIGHT`) |
| 대본 생성 | 약 2분 30초 | 그대로 | 섹션마다 앞 섹션 흐름을 이어받아서 병렬화하지 않음 |

39분 강의 전체 추정: 대본 약 2분 30초 + 음성 약 2분 30초(4장 실측에서 비례 추정) + 조립 약 35초 ≈ **6분 안팎** (NAS CPU는 조립이 더 느릴 수 있음).
