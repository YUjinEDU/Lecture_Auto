# Single-Screen Unified Job View — Design Spec

**Date:** 2026-04-13  
**Status:** Approved  
**Scope:** Demo UI (`homepage/`) — Job 상세 페이지의 3-탭(진행상황·슬라이드검수·다운로드)을 단일 스크롤 화면으로 통합

---

## 1. 목표

교수님이 탭 전환 없이 하나의 화면에서:
1. 파이프라인 완료 여부를 확인하고
2. 슬라이드별 스크립트를 검수·편집하고
3. 완성된 파일을 선택적으로 다운로드

할 수 있도록 Job 상세 페이지를 단일 스크롤 레이아웃으로 재구성한다.

---

## 2. 상태 머신 (State Machine)

화면은 Job 상태에 따라 자동으로 레이아웃을 전환한다. 사용자가 탭을 선택하지 않는다.

| 상태 | 표시 내용 |
|------|-----------|
| `running` | Job 헤더 + 진행 상황(메인) + 검수 placeholder |
| `completed` | Job 헤더 + 진행 요약(접힘) + 슬라이드 검수 + 다운로드 |
| `failed` | Job 헤더 + 에러 메시지 + 재시도 버튼 |

---

## 3. 레이아웃 상세

### 3-A. 공통 헤더

모든 상태에서 상단에 고정.

```
┌──────────────────────────────────────────┐
│  강의자료 제목          ● 처리중 / ✅ 완료 / ❌ 실패  │
│  Job ID: abc123-def456   시작: 2026-04-13 14:32  │
└──────────────────────────────────────────┘
```

### 3-B. 처리중 (running)

```
┌──────────────────────────────────────────┐
│  [공통 헤더]                              │
├──────────────────────────────────────────┤
│  진행 상황 (메인)                         │
│  ① PPT 파싱      ✅ 완료                 │
│  ② 슬라이드 렌더링 ✅ 완료               │
│  ③ VLM 분석      ⏳ 진행중 (3/12)        │
│  ④ 스크립트 생성  ─ 대기                 │
│  ⑤ TTS 생성      ─ 대기                 │
│  [로그 보기 ▾] (기본 접힘)              │
├──────────────────────────────────────────┤
│  슬라이드 검수                            │
│  ⏳ 파이프라인 완료 후 열립니다           │
└──────────────────────────────────────────┘
```

### 3-C. 완료 (completed)

```
┌──────────────────────────────────────────┐
│  [공통 헤더]                              │
├──────────────────────────────────────────┤
│  ▶ 진행 요약 (기본 접힘, 클릭 시 펼침)   │
├──────────────────────────────────────────┤
│  슬라이드 검수 (메인)                     │
│  ┌──────────┬─────────────────────────┐  │
│  │슬라이드  │ [슬라이드 PNG]          │  │
│  │목록      ├─────────────────────────┤  │
│  │          │ 스크립트 텍스트 에디터  │  │
│  │1 ●       │                         │  │
│  │2         │ [재생성] [승인→TTS시작] │  │
│  │3         │                         │  │
│  └──────────┴─────────────────────────┘  │
├──────────────────────────────────────────┤
│  다운로드                                 │
│  ☑ 음성 (WAV)  전체  240MB  ↓           │
│  ☑ 음성 (MP3)  전체   48MB  ↓           │
│  ☑ 스크립트    전체    8KB  ↓           │
│  ─────────────────────────────────────── │
│  슬라이드별: S1 음성↓ 스크립트↓  …      │
│  [선택 항목 ZIP 다운로드]                │
└──────────────────────────────────────────┘
```

### 3-D. 실패 (failed)

```
┌──────────────────────────────────────────┐
│  [공통 헤더]                              │
├──────────────────────────────────────────┤
│  ❌ 오류 발생                             │
│  오류 메시지 상세                         │
│  [로그 보기 ▾]                           │
│  [재시도]                                │
└──────────────────────────────────────────┘
```

## 4. 슬라이드 검수 상세

Phase 3 결정 유지:
- **2-패널 분할**: 좌측 슬라이드 목록(썸네일), 우측 슬라이드 PNG + 스크립트 에디터
- **슬라이드별 재생성 버튼**: 체크박스 일괄 선택 아님
- **승인 버튼 = TTS 자동 시작**: 별도 확인 단계 없음, API 호출: `POST /api/jobs/{id}/slides/{n}/approve`
  - 서버는 승인 저장 후 TTS 태스크를 즉시 큐에 등록
  - 응답: `{ "status": "ok", "slide": n, "tts": "queued" }`

### 스크립트 에디터 저장/dirty 정책
- **자동 저장**: blur(포커스 이탈) 시 `PATCH /api/jobs/{id}/slides/{n}/script` 자동 호출
- **dirty 상태 표시**: 저장 전 에디터 우측 상단에 "저장 중…" 인디케이터
- **재생성 충돌**: 편집 중인 내용이 있을 때 [재생성] 클릭 시 "편집 내용이 사라집니다. 계속할까요?" 확인 다이얼로그 표시

### 모바일 (< 768px) 레이아웃
- 슬라이드 목록: 가로 스크롤 썸네일 스트립 (상단 고정, 높이 72px)
- 슬라이드 뷰 + 스크립트: 아래 단일 컬럼

## 5. 다운로드 섹션 — 3단계 활성화 모델

`completed` 상태에서 섹션이 나타나지만, 내부 버튼 활성화 수준은 3단계로 나뉜다.

| 단계 | 조건 | 표시 |
|------|------|------|
| **잠김** | TTS 완료 슬라이드 0개 | 섹션 표시, 전체 버튼 비활성 + "TTS 생성 대기 중" |
| **부분 활성** | TTS 완료 슬라이드 1개 이상, 전체 미완료 | 완료 슬라이드별 버튼 활성, 전체 행은 "N/M 완료" 표시 |
| **완전 활성** | 전체 슬라이드 TTS 완료 | 전체 행 + 슬라이드별 전부 활성, ZIP 버튼 활성 |

### 전체(통합) 다운로드 행
- 부분 활성 상태에서는 전체 행을 비활성으로 표시하고 "N/M 슬라이드 완료" 라벨을 함께 표시
- 완전 활성 시 크기 표시 및 다운로드 버튼 활성화

### ZIP 다운로드
- 완전 활성 시에만 표시
- 검수 미승인 슬라이드가 있으면 "일부 슬라이드가 미승인 상태입니다. 그래도 다운로드할까요?" 확인 후 진행

### 파일 목록
| 항목 | 설명 |
|------|------|
| 음성 (WAV) | 원본 품질, 전체 또는 슬라이드별 |
| 음성 (MP3) | 압축, 전체 또는 슬라이드별 |
| 스크립트 (TXT) | 검수·편집된 최종 스크립트 |

## 6. 반응형 브레이크포인트

| 구간 | 슬라이드 목록 | 뷰 영역 |
|------|-------------|---------|
| `< 768px` (모바일) | 상단 가로 스크롤 썸네일 스트립 (72px 고정) | 아래 단일 컬럼 |
| `768px–1024px` (태블릿) | 좌측 120px 세로 목록 | 우측 나머지 |
| `> 1024px` (데스크탑) | 좌측 200px 세로 목록 | 우측 나머지 |

## 7. 데이터 흐름

### SSE 이벤트 스키마 (`/api/jobs/{id}/stream`)

| `type` | payload | 동작 |
|--------|---------|------|
| `step_update` | `{ step: 1-5, status: "running"\|"done"\|"failed", detail: string }` | 진행 상황 스텝 업데이트 |
| `job_complete` | `{ job_id: string }` | 레이아웃 `running` → `completed` 전환 |
| `job_failed` | `{ job_id: string, error: string }` | 레이아웃 `running` → `failed` 전환 |
| `tts_done` | `{ slide: number }` | 해당 슬라이드 다운로드 버튼 활성화 |

### 폴링 fallback
- SSE 미지원 환경에서 3초 간격 `GET /api/jobs/{id}`
- 응답 스키마: `{ status: "running"|"completed"|"failed", steps: [...], tts_done_slides: number[] }`
- 프론트 상태 머신은 SSE 이벤트와 폴링 응답을 동일한 내부 액션으로 처리

### 재시도 (failed 상태)
- `POST /api/jobs/{id}/retry`
- 파이프라인은 **실패한 스텝부터** 재시작 (이미 완료된 스텝 결과 재사용)
- 재시도 후 상태는 즉시 `running`으로 전환, 화면 레이아웃도 즉시 전환

---

## 8. 제거 항목

- 기존 탭 컴포넌트 (진행상황·슬라이드검수·다운로드 탭) 전면 제거
- 탭 상태 관리 (`activeTab` state) 제거

---

## 9. 미결 사항

- 슬라이드 수가 많을 때(30장+) 좌측 목록 가상 스크롤 필요 여부 → Phase 후속 검토
- ZIP 생성: 프론트 client-side(JSZip) vs 백엔드 엔드포인트 → 구현 시 결정
