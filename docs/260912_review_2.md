원래 어려운 슬라이드여서인지 이 데이터로는 분리되지 않습니다. 4/5 통과도 재추출이
살린 것인지 재추출 없이도 통과했을 것인지 알 수 없습니다.

## 4. 공식 vLLM-omni 경로 — 사전 확인만

`docs/260911_강의영상제작/Raon-Speech-9B.md` 155~200줄에 공식 절차가 있습니다.

```bash
git clone https://github.com/krafton-ai/vllm-omni.git
docker build -f docker/Dockerfile.ci -t vllm-omni .
docker run --rm --gpus all --shm-size=16g -p 8000:8000 vllm-omni \
  bash -c "vllm serve KRAFTON/Raon-Speech-9B --omni --port 8000 --trust-remote-code"
```

### 확인된 사실

| 항목 | 상태 |
|---|---|
| Docker | 29.6.1, 데몬 접근 가능 |
| GPU | RTX A6000 2장, 드라이버 535.309.01 |
| 현재 환경 vllm | 미설치 (건드리지 않음) |
| 격리 | Docker 이미지라 현재 venv와 완전 분리됨 |

Docker로 도는 구조라 **현재 환경 패키지를 바꾸지 않고 시험할 수 있습니다.**
이게 이 경로의 가장 큰 장점입니다.

### 미확인 — 가정하면 안 되는 것

- **음성 복제 동등성.** 서버 예제는 `ref_audio` + `task_type: "Base"`를 씁니다.
  현재 파이프라인은 `tts_continuation`으로 직전 세그먼트를 프리필해 연결부를
  매끄럽게 만듭니다. 서버 API에 이에 해당하는 것이 있는지 문서에서 확인되지
  않습니다. 없다면 세그먼트 경계가 지금보다 거칠어질 수 있습니다.
- **속도 향상 폭.** 공식 벤치마크는 영어 기준입니다. 한국어에서, 우리 세그먼트
  길이 분포에서, A6000에서 얼마가 나올지는 재봐야 압니다.
- **A6000 지원.** 문서에 명시가 없습니다. 빌드와 기동을 해봐야 합니다.
- **빌드 성공 여부.** Dockerfile.ci를 빌드해본 적이 없습니다.

### 제안하는 비교 방법

GPU가 비면, 같은 한국어 문장 12개와 같은 기준 음성(`reference_v1.wav`)으로
현재 Python 경로와 서버 경로를 비교합니다. 평가 항목은 소요 시간, 누락·반복,
목소리 유사도, 문장 연결부 자연스러움입니다. 연결부는 서버에 continuation이
없을 수 있으므로 특히 주의해서 봐야 합니다.

**아직 아무것도 설치하거나 빌드하지 않았습니다.** 현재 배치가 GPU 2장을 모두
쓰고 있어 빌드가 경쟁을 일으킬 수 있고, 지시에도 환경 변경 금지가 있었습니다.
