# 아이디어: 강의자료 + 수업 녹음 → 재구성 노트·위키·영상

작성: 2026-10-05 · 상태: **아이디어(미착수)** · 근거 조사: [`PRIOR_ART_RECORDING_20261005.md`](../hardening/00_context/PRIOR_ART_RECORDING_20261005.md), [`PRIOR_ART_20261005.md`](../hardening/00_context/PRIOR_ART_20261005.md)

## 배경
- 현재 Lecture Auto는 **교수용** 도구: 교수님 PPT → 비대면 강의 영상(대본 생성 + 음성 + 자막 + 하이라이트).
- 약점: 대본을 LLM이 **슬라이드만 보고 지어낸다** — 말투는 흉내 내도 교수님이 실제로 한 설명·예시가 아니다.
- 학생 입장에는 **강의자료 + 수업 녹음**이 이미 있다. 이걸 묶어 수업을 이해하기 쉽게 다시 정리해주는 도구가 있으면 좋겠다.

## 개념
> 강의자료(PDF/PPTX) + 수업 녹음(오디오, 가능하면 화면 녹화) → 슬라이드별로 **교수님이 실제로 한 설명**을 정리한 노트 → 학기 전체를 잇는 **위키** → (선택) 교수님 톤의 재구성 **영상**

전제: **슬라이드는 생성하지 않는다.** 언제나 기존 자료를 그대로 쓴다. 한국어 우선, 영어 확장 예정.

## 파이프라인과 재사용
| 단계 | 상태 |
|---|---|
| 강의자료 파싱·렌더 | 재사용 (`pipeline/parser_pdf.py`, `renderer.py`) |
| 녹음 → 타임스탬프 전사 | 신규 — 기본 Whisper large-v3-turbo(faster-whisper, 로컬), 대안 OpenAI 전사 API(90분 ≈ $0.54) |
| 전사 ↔ 슬라이드 정렬 | 신규(핵심) — S15 하이라이트 매핑(문장↔텍스트 블록)을 슬라이드 단위로 확장 + 순서 제약(DP). 화면 녹화가 있으면 프레임↔슬라이드 매칭으로 정답 자동 생성 |
| 전문용어 오인식 표시 | 신규 — 슬라이드 텍스트와 대조해 의심 단어 표시(자동 치환 X). S13 `--check`와 같은 발상 |
| 슬라이드별 재구성 노트 | 재사용 확장 — 섹션 대본 생성·S12 말투 재작성 틀, 입력을 "슬라이드" → "슬라이드 + 실제 발화"로. 문장마다 녹음 시각 근거 링크 |
| 학기 위키 | 신규 — 강의 노트 + 개념 페이지, 주차 간 링크(S16a 메모리 확장), Obsidian 호환 마크다운 |
| 재구성 영상 | 재사용 — TTS + S14 자막 + S15 하이라이트 |

## 진행 순서(안)
1. 위키 1페이지 시험판: 녹음 1개 + 자료 1개 → 전사 → 정렬 → 슬라이드별 노트(근거 시각 링크). GPU 불필요.
2. 여러 강의 → 개념 페이지·상호 링크(학기 위키).
3. 재구성 영상(기존 파이프라인 출력 모듈로).

## 방향 결정 (2026-10-05)
- **오픈소스 + 우리 연구실이 먼저 쓰기**가 주목표. 논문은 부산물.
- 이유: 논문은 여러 강의 데이터·학생 평가·비교 실험이 필요해 지금은 비용 대비 근거 부족. 쓰면서 쌓인 결과물이 나중에 그대로 데이터가 된다.
- 단, 비교군 옵션(슬라이드만 / 전사만 / 슬라이드+전사 정렬)을 남겨 두면 나중에 실험이 거의 공짜.

## 경쟁·차별점 (조사 요약)
- 상용(NotebookLM/Gemini Notebook, 클로바노트, 다글로, 릴리스): 전사 + 요약 중심. 슬라이드별 실제 발화 정렬·교수 톤·학기 위키는 확인 안 됨(2차 자료 — NotebookLM은 직접 재확인 필요).
- 오픈소스 최근접: `drpwchen/lecture-to-notes`(★106, MIT — Whisper + 슬라이드 정렬 + Obsidian, 한국어·위키·영상 없음). 유사 프로젝트가 최근 몇 달 사이 급증 → 선점 효과 짧음.
- 우리 차별점: **통합(정렬 + 근거 인용 + 위키 + 영상) + 한국어 우선 + 문장별 근거 시각 링크**.
- 논문 주장 후보(KCC/워크숍급): "슬라이드에 정렬되고 실제 발화를 인용 근거로 단 재구성이 슬라이드만 생성·전사만 요약보다 인용 정확도·커버리지가 높다." 영어 벤치마크는 CMU LPM(슬라이드 전환 주석, 영상은 YouTube ID만), 한국어는 소규모 정답 세트를 직접 만들어야 함.

## 오픈소스로 낼 때 필요한 것
3분 데모(CC 라이선스 샘플로) · 한 줄 CLI · 한국어 용어 표시 · Obsidian 호환 위키 · 로컬 전사 기본 · 문장→녹음 시각 추적 · 평가 스크립트 동봉.

## 위험
1. 수업 녹음·교수 음성 복제 **동의** — 공개판은 음성 복제 기본 끔, 기본값은 "교수 말투 대본 + 중립 음성".
2. 슬라이드·녹음 **저작권** — 저장소에 데이터 포함 금지, 사용자가 자기 파일을 넣는 구조.
3. 한국어 전문용어 전사 오류가 노트로 새는 문제.
4. 톤 흉내가 "교수가 하지 않은 말"로 읽힐 위험 → 근거 링크 필수.
5. 빠른 경쟁·모델 라이선스(turbo 한국어 파인튜닝은 상업 라이선스 필요 등) 의존.

## 열린 질문
- 시험용 자료 + 녹음 짝: 사용자가 별도 제공 예정(현재 `data/PDF/AI현업문제해결/`의 2025 녹음은 쓰지 않음 — 자료 버전도 다름).
- 위키 형식(Obsidian 볼트? 정적 사이트?), 개념 페이지 단위.
- 이 기능을 이 저장소에 둘지, 별도 오픈소스 저장소로 분리할지.
