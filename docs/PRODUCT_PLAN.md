# 제품 기획안: Lecture Auto를 여러 사람이 쓰는 서비스로

작성: 2026-11-07 · 상태: **기획(미착수)**

## 1. 한 줄 정의

> **교수님 슬라이드 → 교수님 목소리 강의영상 → 학생이 보기 좋은 강의 페이지**

- 만드는 사람: 교수자(가입 사용자). 지금의 업로드 → 대본 검토 → 음성 → 승인 → 영상 흐름 그대로.
- 보는 사람: 학생(가입 없음). 교수자가 준 공유 링크로 강의 페이지를 본다.
- 학생이 직접 만드는 "학생용 생성기"는 별도 제품으로 만들지 않는다. 경쟁이 많고(NotebookLM 등), 보이스 클로닝·사람 검토라는 우리 강점이 쓸모없어지고, 남의 자료를 영상화하는 저작권 문제가 생긴다. 녹음 기반 학생 복습 아이디어(`docs/ideas/IDEA_recording_to_wiki.md`, `docs/interactive_lecture_player/plan.md`)는 이 제품이 자리 잡은 뒤의 확장 후보로 남긴다.

## 2. 대상과 확정된 결정

| 항목 | 결정 |
|---|---|
| 사용자 | 같은 학교 교수님 몇 분 + 외부 공개 가입 |
| API 비용 | **사용자가 자기 API 키를 넣는다(BYO key).** 운영자는 API 비용을 내지 않는다 |
| TTS | 로컬 모델과 API 둘 다 지원 |
| 보이스 클로닝 | **음성 파일 업로드로 복제 허용** |

### 결정에 따라오는 필수 사항

**BYO key**
- 키는 서버에 암호화해서 저장한다(서버 비밀키로 대칭 암호화). 화면·로그·작업 기록에 원문을 절대 남기지 않는다. 화면에는 끝 4자리만 보인다.
- 키를 등록할 때 가벼운 호출로 유효성을 검사한다.
- 작업 전에 예상 사용량(대본 글자 수, TTS 글자 수/분)을 보여 준다. 비용은 사용자 계정에서 나가므로, 모르고 큰 비용이 나가는 일을 막는 게 신뢰의 핵심이다.
- LLM(대본 생성)과 TTS의 키는 따로 받는다. 지금 대본 생성은 OpenAI 호환 게이트웨이(`FACTCHAT_*`)를 쓰므로, "OpenAI 호환 base URL + 키" 형태로 받으면 그대로 맞는다.

**업로드 음성 복제** (본인 확인 없이 허용하므로 책임을 분명히 하는 장치가 필요)
- 업로드할 때 "이 목소리의 주인이 본인이거나 사용 동의를 받았다"는 체크를 필수로 받고, 동의 시각·계정·파일 해시를 기록한다.
- 복제 음성으로 만든 영상에는 "AI 합성 음성" 표기를 기본으로 넣는다(강의 페이지와 영상 끝 자막).
- 신고 접수와 삭제 절차를 이용약관에 둔다. 신고된 음성은 즉시 비활성화한다.
- 음성은 계정 밖으로 공유되지 않는다(다른 사용자가 고를 수 없음).

**로컬 TTS 라이선스**
- 현재 로컬 모델 Raon-Speech-9B는 **CC BY-NC 4.0(비상업)**이다. 외부 공개 서비스에서 기본 엔진으로 쓰지 않는다. 로컬 엔진은 직접 설치해서 쓰는 경우와 학교 내부용에서만 켠다.

## 3. 기능 범위

### 교수자 (만드는 쪽)
1. 가입·로그인(이메일), 계정별 저장 공간 분리
2. API 키 설정(LLM, TTS 공급자별)
3. 내 음성 관리: 업로드 → 동의 체크 → 미리 듣기 → 기본 음성 지정
4. 강의 만들기: 지금 웹 UI의 흐름 유지(대본 생성 → 검토·수정 → 음성·영상 → 확인 필요 → 승인 → 조립)
5. 공유: 강의별 공유 링크 발급·회수, 공개 범위(링크 아는 사람 / 비공개)

### 학생 (보는 쪽, 강의 페이지)
| 기능 | 기반 | 단계 |
|---|---|---|
| 영상 + 자막 | S14 자막(`pipeline/subtitles.py`, SRT/VTT) | 1차 |
| 슬라이드 하이라이트 | S15 하이라이트(`pipeline/highlight.py`, 문장 ↔ 슬라이드 글 블록 매칭) | 1차 |
| 챕터 목차(슬라이드 제목 타임라인) | 파싱 결과의 슬라이드 제목 + 슬라이드별 음성 길이 | 1차 |
| 대본 전문 + 문장 클릭 시 해당 시점으로 이동 | 자막 cue 시각 | 1차 |
| 핵심 용어 정리 | LLM 생성 → 교수자 검토 후 공개 | 2차 |
| 슬라이드별 확인 퀴즈 | LLM 생성 → 교수자 검토 후 공개 | 2차 |

하지 않는 것: 슬라이드에 없는 다이어그램·차트를 LLM이 새로 그리기(틀린 내용 위험), 말하는 아바타(비용 대비 효과 없음).

원칙: 학생에게 보이는 생성물(퀴즈·용어)은 대본과 같이 **교수자가 검토·승인한 것만** 공개한다. "사람이 검토한다"는 지금의 강점을 학생 쪽까지 이어 간다.

## 4. 기술 구조 변경

### 4.1 코어를 라이브러리로 (가장 먼저)
- 지금 웹은 `scripts/batch_generate_lectures.py`·`scripts/produce.py`를 subprocess로 실행하고, 강의 목록은 CLI의 `LECTURES` + `data/web/lectures.json`이다.
- 바꿀 것: `Project`(강의) / `Job`(작업) / `Artifact`(대본·음성·영상) 단위의 파이썬 API를 만들고 웹과 CLI가 둘 다 이걸 호출한다. GPU·LLM 작업은 중단·GPU 메모리 회수·웹 재시작 후 생존을 위해 계속 별도 프로세스로 돌리되, 넘기는 것을 CLI 인자 + 환경변수에서 작업 명세 파일로 바꾼다.
- 강의 번호로 갈리는 설정(참조 음성 v1/v2, 마스터링 on/off, GPU 번호)은 **강의별 설정 파일**로 옮긴다.
- 유지할 것: 파일이 진실의 원천, 사람이 읽고 고칠 수 있는 대본 형식, 같은 입력 → 같은 결과.

### 4.2 TTS 공급자 추상화
- `lecture_auto/tts/`에 이미 `TTSEngine` 인터페이스와 등록 구조가 있다(현재 등록된 것은 Qwen뿐). 실제 제작에 쓰는 Raon은 `pipeline/raon_tts.py`에 따로 있다. **Raon을 이 인터페이스로 옮기고**, API 공급자를 같은 인터페이스로 추가한다.
- 공급자마다 지원 기능을 선언한다: 업로드 음성 복제 가능 여부, 한 번에 보낼 수 있는 최대 글자 수, 발음 교정 방식.
- **주의: 자막 시각 복원 방식.** S14 자막은 Raon이 문장 조각 사이에 정확히 0인 무음 구간을 넣는다는 점을 이용해 WAV에서 문장 시각을 복원한다. API 공급자에도 그대로 쓰려면 **문장 조각 단위로 합성한 뒤 우리 쪽에서 0 무음으로 이어 붙이는** 방식을 공통 규칙으로 둔다. 그러면 자막·하이라이트가 공급자와 상관없이 동작한다.
- 캐시 키 = 공급자 + 모델 + 음성 ID + 문장 해시. API는 같은 입력에도 결과가 달라질 수 있으므로, 재현성은 "다시 부르지 않고 캐시 재사용"으로 지킨다. 이미 만든 슬라이드를 다시 합성하지 않는 것은 비용 절약에도 직결된다.
- 발음 점검·보류(DRAFT) 처리 등 검사 단계는 공급자와 무관하게 똑같이 돈다.

### 4.3 계정과 작업 큐
- DB: SQLite(사용자, API 키(암호화), 음성, 강의 메타, 공유 링크, 작업). 강의 산출물은 계속 파일로 두고 사용자별 폴더로 나눈다.
- 작업 큐: SQLite 기반. 작업자를 두 종류로 나눈다.
  - GPU 작업자: 로컬 TTS. 한 번에 하나(GPU 0만 사용, GPU 1은 다른 사람 학습용이므로 쓰지 않음).
  - API 작업자: 대본 생성·API TTS·영상 조립. 사용자별 동시 실행 수 제한을 두고 병렬 실행.
- Celery/Redis는 다시 들이지 않는다(2026-10-25에 걷어냄).

### 4.4 배포
- 공개 서비스: 학교 서버 + 리버스 프록시(HTTPS, 요청 크기·횟수 제한). 업로드 용량과 사용자별 저장 공간 한도를 둔다.
- 설치형: `docker compose up` 한 번으로 실행. 로컬 GPU TTS는 선택 사항.

## 5. 진행 순서

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| 1 | 코어 라이브러리화 + 강의별 설정 ([설계](STAGE1_CORE_DESIGN.md)) | 웹이 CLI 인자·환경변수 대신 코어 API와 작업 명세로 지금 기능을 전부 수행(GPU·LLM 작업은 계속 별도 프로세스), 기존 TTS 캐시 키 불변, 기존 테스트 통과 |
| 2 | TTS 공급자 추상화(Raon 이전 + API 공급자 1개) | 같은 강의를 Raon과 API로 각각 만들어 자막·하이라이트·검사가 둘 다 동작 |
| 3 | 계정·BYO key·음성 업로드(동의 기록) | 두 계정이 서로의 강의·음성·키를 볼 수 없음, 키 원문이 로그·DB 평문에 없음 |
| 4 | 공유 링크 + 학생 강의 페이지(1차 기능) | 로그인 없이 링크로 영상·자막·하이라이트·챕터·대본 이동이 동작 |
| 5 | 용어·퀴즈(교수자 검토 후 공개) | 검토 안 된 생성물은 학생 페이지에 나오지 않음 |
| 6 | 공개 가입 오픈 | 이용약관·신고 절차, 업로드·저장 한도, HTTPS 프록시 |

같은 학교 교수님들께는 3단계가 끝나면 초대 방식으로 먼저 열고, 외부 공개 가입은 6단계에서 연다.
